## AI-Hub 금융 고객상담

### 구성

| Split | 원천 상담 | 라벨 QA |
| --- | ---: | ---: |
| Train | 58,475 | 80,000 |
| Validation | 6,787 | 10,000 |

원천과 라벨의 `source_id` 연결률은 양 Split 모두 100%다. 상담 하나에 여러 QA가 생성될 수 있어 라벨 파일 수가 원천 상담 수보다 많다. Train과 Validation 사이에 동일 `source_id` 3개가 존재하므로 정규화 단계에서 원문 해시까지 비교해 누수를 제거한다.

### Schema

원천 JSON:

- `source`: 기관, ID, 날짜, 고객 성별·연령, 상담 대상, 상담 원문, 길이
- `consulting`: 금융 영역과 상담 주제

라벨 JSON은 원천 필드에 다음을 추가한다.

- `consulting_summary`
- `qa_data`: 상담 상황, 목적, 질문·답변·후속 질문, 출력, 핵심 금융 용어

허용해야 하는 타입 변형:

- `consulting_client_type`: 문자열 또는 `null`
- `core_financial_terms`: 문자열 또는 `null`
- 원천 `source_date`: 정수, 라벨 `source_date`: 문자열

라벨 Task는 `핵심 금융 용어` 78,560건과 `일반 상담` 11,440건이다.

### FinPass 활용

- 은행 상담을 우선 사용해 상담 Summary와 Similar Case Corpus를 구축한다.
- 보험·증권 데이터는 금융 문체와 일반 상담 평가에 보조 사용한다.
- `consulting_content`, 질문, 답변은 비식별 검사 후에만 RAG Corpus로 보낸다.
- `client_gender`, `client_age`는 Segment 분석용 별도 테이블에 두고 Embedding Text에서 제외한다.

## AI-Hub 금융상품·소비자 특성

### 구성

- 상품 원천: 증권 8,000개, 보험 2,000개
- 추천 CoT: Train 8,000개, Validation 1,001개
- 소비자 CSV: 385,019행, 22열

상품 원천의 Train/Validation 13개 ZIP 쌍은 압축 메타데이터와 무관하게 내부 내용이 완전히 동일하다. 소비자 Train/Validation CSV도 동일하다. 따라서 이 제공 Split은 모델 평가 분리로 사용할 수 없다.

### Schema와 품질 이슈

- 증권 상품: 상품명, 보호·만기·수익률·위험등급·과세·손실·유동성·전략
- 보험 상품: 회사, 상품·특약, 가입연령, 납입·보장·환급·갱신 조건
- CoT: 성별·연령, Query 유형, 질문, 3단계 추론, 답변, 상품명 목록
- 소비자: 고객 ID, 연령·성별·지역·소득·직업·신용·질병이력·거래정보

발견된 정규화 이슈:

- 일부 파일명의 확장자가 `.json `으로 끝난다.
- CoT 4건에서 `product_names`가 배열이 아닌 문자열이다.
- 보험 필드에 `minimum_insured _premium`, `srarting_age`처럼 원본 오탈자가 있다.
- 소비자 CSV에는 준식별자와 민감 가능 필드가 있으므로 원문 RAG 및 LLM 입력에서 제외해야 한다.

### FinPass 활용

- 상품 JSON은 Train/Validation을 합치지 않고 내용 해시 기준 한 번만 적재한다.
- MVP 대출 상품과 직접 일치하지 않으므로 상품 Schema 설계와 검색 Pipeline 검증에 사용한다.
- CoT 답변은 업무 사실의 근거로 사용하지 않고 추천 표현·검색 평가용 보조 자료로 제한한다.
- 소비자 CSV는 집계·Synthetic Segment 분포용으로만 사용하고 개인 단위 추천에는 사용하지 않는다.

## BPI Challenge 2017

- Event: 1,202,267건
- Case: 31,509개
- Activity: 26개
- 기간: 2016-01-01 ~ 2017-02-01 UTC
- Event Origin: Workflow 768,823 / Application 239,595 / Offer 193,849
- Lifecycle에는 `schedule`, `start`, `complete`, `suspend`, `resume`, `withdraw`, `ate_abort`가 존재한다.

Work Item Lifecycle Event가 다수이므로 Activity 이름만 FinPass 단계로 치환하면 중복 단계가 과다 생성된다. Application/Offer Event와 Workflow의 완료 Event를 구분하고, Case별 순서·소요시간·반복 패턴을 Synthetic 생성 근거로 사용한다.

## Banking77

- Train 10,003건, Test 3,080건
- `text`, `label`, `label_text`
- 77개 Intent가 양 Split에 모두 존재
- MIT 라이선스, 고정 리비전 `18072d2`

영어 온라인 뱅킹 문의이므로 국내 개인사업자 대출의 정답 Label로 직접 사용하지 않는다. Intent Classifier Baseline과 내부 Taxonomy의 미매핑 탐지에 사용한다.

## 결정 사항

1. AI-Hub 원문은 비식별 검사를 통과하기 전까지 Embedding하지 않는다.
2. 금융상품 원천 및 소비자 CSV의 중복 Validation은 평가에서 제외한다.
3. BPI는 Process 분포의 근거이며 FinPass 모바일 Event의 직접 정답이 아니다.
4. 모든 변환은 원본 파일명, 원본 ID, Dataset Split, Schema Version을 추적한다.
5. 생성된 학습·평가 Split은 `source_id` 또는 내용 해시를 기준으로 Group 분할한다.
